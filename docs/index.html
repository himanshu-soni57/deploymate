Command reference

Every DeployPilot command, and what it is for.

DeployPilot reads your .github/workflows, works out how each one can actually be triggered, does the Git or API work to start it, then watches the run and tells you whether it worked. Start with the recipes if you know the outcome you want but not the flag.

Install Then, in any repo

Two binaries are installed: deploypilot and the short alias dpp. Both are used interchangeably below.

Commands

Sixteen commands. local works with plain Git and no token; api needs GitHub API access; writes changes your repository or your remote.

dpp deploy [environment] Commit, push or dispatch, and start a workflow run. The default command. writes

Discovers workflows, ranks the strategies each one supports, runs preflight checks, then commits and pushes, creates and pushes a tag, dispatches, or publishes a release — whichever the workflow actually listens for.

-w, --workflow <file>
Workflow file or name. Skips the picker.
-s, --strategy <kind>
How to trigger it. tag · branch · dispatch · release
-m, --message <message>
Commit message. Required when committing non-interactively.
-a, --all
Commit every change in the working tree.
-f, --file <path...>
Commit only these files. Repeatable, globs allowed. Everything else stays uncommitted.
--staged
Commit exactly what is already in the index.
--no-commit
Commit nothing; deploy the commits that already exist.
-t, --tag <name>
Use this exact tag. Rejected if the workflow's filter would ignore it.
-r, --ref <ref>
Tag or dispatch this commit instead of HEAD.
-b, --bump <type>
Version bump for tag strategies. major · minor · patch · prerelease · auto
--sign
Create a GPG-signed tag instead of a plain annotated one.
--release
Also publish a GitHub Release, with the changelog as its body.
-i, --input <key=value...>
workflow_dispatch inputs. Repeatable.
--no-fetch
Skip fetching the remote during preflight. Use when offline.
--no-push
Do everything locally but push nothing.
--watch
Follow the run and report its outcome. Exits non-zero on failure.
--empty-commit
Create an empty commit when there is nothing left to push.
--signoff
Add a Signed-off-by trailer to the commit.
--dry-run
Show every action without performing any of them.
-y, --yes
Accept defaults and skip confirmations.
--force
Continue past failed preflight checks.
dpp watch [run-id] Follow a workflow run and surface failing steps. api

With no run id, picks the latest active run on your branch. Detects runs blocked on an environment reviewer and says so rather than appearing hung.

-w, --workflow <file>
Restrict to this workflow.
-b, --branch <name>
Restrict to this branch.
dpp status Show in-flight runs, environment state, and recent history. api
-n, --limit <count>
How many recent runs to show.
dpp history List past deployments with who, when, duration, and outcome. api
-n, --limit <count>
How many runs to list.
-w, --workflow <file>
Restrict to this workflow.
-b, --branch <name>
Restrict to this branch.
-e, --event <event>
Restrict to this trigger event.
--failed
Only show runs that did not succeed.
dpp logs [run-id] Print logs for a run, failing steps first. api

Defaults to the most recent run, and to only the jobs that failed — the log tail around the error, not megabytes of output.

-j, --job <name>
Only this job. Matched as a substring.
--no-failed-only
Print every job's full log instead.
dpp cancel [run-id] Cancel a workflow run. api
-y, --yes
Skip the confirmation prompt.
dpp rerun [run-id] Re-run a workflow run. api
--failed
Only re-run the jobs that failed.
--watch
Follow the new run.
-y, --yes
Skip the confirmation prompt.
dpp rollback Re-deploy a previous successful run. api

Prefers dispatching the workflow at that run's commit; falls back to GitHub's own re-run when the workflow has no workflow_dispatch trigger. Requires typing rollback to confirm, because it re-deploys old code.

-w, --workflow <file>
Workflow to roll back.
--run <id>
Roll back to this run id or run number.
-i, --input <key=value...>
workflow_dispatch inputs.
--watch
Follow the rollback run.
-y, --yes
Skip the typed confirmation.
dpp doctor Audit workflows for security, correctness, and cost problems. local

Runs the structural checks from lint plus 12 audit rules. Secret checks are skipped when no GitHub token is available. Exits non-zero when any error is found.

--only <rule...>
Run only these rule ids.
--skip <rule...>
Skip these rule ids.
--strict
Exit non-zero on warnings too, not just errors.
dpp lint Validate workflow YAML with line-accurate errors. local

Catches unknown events, jobs with no runs-on, steps with both uses and run, needs pointing at jobs that do not exist, and unknown keys — before a push burns CI minutes.

dpp explain [workflow] Describe in plain English when and how a workflow runs. local

Renders the trigger conditions, the job graph, approval-gated environments, token permissions, and the exact DeployPilot command that would trigger each path.

dpp list (alias: ls) List discovered workflows and how they can be triggered. local

Shows every workflow with its trigger events and the strategies DeployPilot can use for it. Workflows nothing can trigger are marked as such.

dpp new Scaffold a workflow from a template. writes
-t, --template <id>
Template id. See Templates.
-o, --output <filename>
File name to write into .github/workflows/.
--dry-run
Print the file instead of writing it.
dpp secrets Compare secrets referenced in workflows against configured ones. api

Catches the classic 2am failure: a workflow that references a secret nobody ever added. Also lists configured secrets nothing uses. Names only — values are never fetched or printed. Exits non-zero when anything referenced is missing.

dpp init Create a config from your existing workflows. writes

Reads your real workflows and asks which should become environments, rather than dumping a generic template you have to correct. Interactive only.

--format <format>
Config format. ts · json
--dry-run
Print the config instead of writing it.
dpp completion <shell> Print a shell completion script. local

Completes command names, workflow files, strategies and bump types. Accepts bash, zsh, or fish.

Staging modes

What goes into the deployment. Offered as a prompt when you run dpp deploy with a dirty working tree, and available as flags for scripts.

ModeFlagWhat happens
Commit all changes -a, --all Everything in the working tree, including untracked files.
Pick specific files -f, --file <path...> A checklist, or explicit paths and globs. Unselected files stay uncommitted. Files that were staged but not selected are unstaged first, so they cannot be swept into a production deploy.
Use the existing index --staged Exactly what git add already put in the index.
Deploy existing commits --no-commit Commits nothing. Tags or dispatches work that is already committed — and possibly already pushed. Combine with --ref to target an older commit.
Credential guard. Selected paths are matched against .env*, *.pem, *.key, id_rsa, credentials.json and similar. A match stops the deployment and asks. Non-interactively it exits 130 unless you pass --yes.
In CI, nothing is guessed. A non-interactive run with a dirty working tree and no staging flag deploys existing commits only. It never assumes you meant to commit.

Tag patterns

Tag names are generated from the workflow's own tags: filter and validated against it. A candidate the filter would ignore is never offered — pushing it would trigger nothing.

Workflow patternDetected asWhat you are offered
v*.*.*semverv1.2.4 · v1.3.0 · v2.0.0 · v1.2.4-rc.0
prod-v*semver, from tag historyprod-v1.2.4
prod-v*timestamp, no semver historyprod-v20260908-141530
release/*timestamp or calverrelease/2026.09.1
v*-rcprefix and suffix preservedv1.2.4-rc
releaseliteralrelease
Bump inference. With Conventional Commits, the bump is read from the commits since the last tag — BREAKING CHANGE or ! gives major, feat gives minor, everything else gives patch — and is marked (recommended) in the picker. The annotated tag carries a grouped changelog with contributors.

Doctor rules

Pass an id to --only or --skip. Rules marked token only run when a GitHub token is available.

Rule idLevelWhat it catches
unreachable-workflowerror A workflow with no on: block, so nothing can ever start it.
untrusted-checkouterror pull_request_target combined with a checkout of the PR head — any fork can then run its own code with access to your secrets.
hardcoded-secreterror A GitHub token, AWS access key, private key, or API key written straight into the workflow.
deprecated-commanderror ::set-output, ::save-state, ::set-env, ::add-path — removed by GitHub and now silent no-ops.
missing-secreterror token A secret the workflow references that the repository does not define.
unpinned-actionwarning An action pinned to a mutable ref like @v4. Whoever controls it can change what runs in your pipeline.
deprecated-actionwarning Action versions GitHub has deprecated or stopped supporting.
missing-permissionswarning No permissions: block, so GITHUB_TOKEN can fall back to repository-wide write access.
missing-concurrencywarning A deployment workflow with no concurrency: group. Two deploys started close together will race.
stale-runnerwarning A runs-on image GitHub has retired.
missing-timeoutnote A job with no timeout-minutes. GitHub's default is 360 minutes of billable runner time.
no-manual-triggernote A deployment workflow with no workflow_dispatch:, so it cannot be re-run without a new commit or tag.

Authentication & exit codes

Tag and branch deployments work with plain Git and no token. Everything marked api above needs one.

OrderSourceNotes
1DEPLOYPILOT_TOKENHighest priority. Use to override everything else.
2GH_TOKENThe GitHub CLI's own variable.
3GITHUB_TOKENSet automatically inside GitHub Actions.
4gh auth tokenIf you already use the GitHub CLI, there is nothing to set up.

The token needs the repo and workflow scopes. GitHub Enterprise Server is detected from the remote URL.

Exit codeMeaning
0Success. For --watch, the run also succeeded.
1Failure — preflight, a failed run, a lint error, or a missing secret.
130Cancelled by the user, or refused at a safety prompt.
